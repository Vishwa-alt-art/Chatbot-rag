That's a solid architecture. Here's the core self-healing loop in LangGraph — when the retriever scores drop below your threshold, we reroute to an expansion node:
def should_requery(state):
    if state["confidence"] < 0.65:
        return "expand_query"
    return "generate"

graph.add_conditional_edges(
    "retrieve", should_requery
)
You can compute confidence from the cosine similarity scores ChromaDB returns. Want me to show the full node logic?

Yes, also how do I pass the expanded query back through the retriever without duplicating documents?
C
Use a seen_ids set in your graph state and filter out already-retrieved chunks before merging:
def expand_query_node(state):
    expanded = rephrase_query(state["query"])
    new_docs = retriever.get_relevant_documents(expanded)
    fresh = [d for d in new_docs
             if d.metadata["id"] not in state["seen_ids"]]
    state["seen_ids"].update(d.metadata["id"] for d in fresh)
    state["docs"] += fresh
    return state
This gives you clean deduplication without a second DB call.

How do I expose this as a Flask endpoint with streaming?
C
Use Flask's Response with stream_with_context:
from flask import Response, stream_with_context

@app.route("/query", methods=["POST"])
def query():
    data = request.json
    def generate():
        for chunk in graph.stream({"query": data["q"]}):
            yield f"data: {chunk}\n\n"
    return Response(stream_with_context(generate()),
                    mimetype="text/event-stream")
Stream each graph node's output as SSE. On the frontend, hook into EventSource to display tokens as they arrive.
